# Foodlog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a self-hosted, single-user food day planner with a local ingredient database, saved meals, Open Food Facts lookup by search and barcode, and calorie/protein targets. It runs in Docker on a Raspberry Pi.

**Architecture:** A zero-dependency Node 24 server (`node:http` + `node:sqlite`) exposes a JSON API under `/api` and serves a vanilla-JS ES-module frontend from `public/`. There is no build step. Pure nutrition, date and constant helpers live in `public/js/shared/`, which both the server and the browser import (one source of truth). Every mutation of a day returns the full updated day, so the UI re-renders from a single response.

**Tech Stack:** Node 24 LTS, `node:sqlite`, `node:test`, vanilla JS/HTML/CSS, `barcode-detector@3.2.3` (ZXing WASM ponyfill, frontend only), ESLint (dev only), Docker + Compose, Tailscale Serve.

**Spec:** `docs/superpowers/specs/2026-10-20-foodlog-design.md`

## Global Constraints

- Runtime npm dependencies: **only** `barcode-detector` (frontend asset). Dev: `eslint`, `@eslint/js`, `globals`. Anything else → ask the user first.
- Node 24 LTS (`node:24-alpine` image). ES modules everywhere (`"type": "module"`).
- All nutrition values are stored **per 100 g**: `kcal, protein, carbs, fat, fiber`.
- Meal slots are fixed and ordered: `breakfast, lunch, dinner, snacks` → labels "Breakfast, Lunch, Dinner, Snacks".
- Default targets: **2000 kcal / 120 g protein**. Default OFF country: `nl`.
- Style "A · Fresh": bg `#f6f8f4`, cards `#fff` with soft shadow `0 2px 8px rgba(30,60,40,.06)`, text `#1d2a22`, muted `#6b7a70`, calorie/action green `#3f9c5f`, protein indigo `#5b6cf0`, over-target amber `#e0a030`. Rounded cards (18–20 px radius), progress rings, round floating "+" button.
- Barcode library files are served from the app (`/vendor/...`) and never from a CDN.
- DB file: `/data/foodlog.db` on a named volume. Container port `8080`. `TZ=Europe/Amsterdam`.
- User-facing text must never be inserted with `innerHTML`. Use the `h()` DOM builder.
- Run tests and lint **through docker compose** (`test` service), not on the host.
- **Never commit automatically.** Each task ends by *suggesting* a conventional-commit message; the developer commits.

## Review Focus

1. **Dutch decimal comma**: on an iPhone with a Dutch keyboard, "12,5" g must parse as 12.5, not fail or become 12 → `parseAmount` tests (Task 1).
2. **"Today" on a UTC server**: edits to an ingredient must update entries from the *Amsterdam* date onward. A 00:30 local edit must not leave tomorrow's plan stale → injected `today()` + compose `TZ` (Task 3 test).
3. **Scanning a product already saved (or archived)**: reuse or restore the existing ingredient. Never crash on the UNIQUE barcode constraint → Task 3 409 test + Task 11 restore flow.
4. **OFF data gaps and outages**: kJ-only energy converts to kcal, products with missing macros come back `complete:false`, and an OFF timeout returns a clean 502 while local search keeps working → Task 4 tests.
5. **Importing a bad file**: invalid or foreign JSON is rejected with a 400 **before** anything is deleted → Task 7 test.

**Interfaces:**
- Produces:
  - `class HttpError extends Error { constructor(status: number, message: string, extra?: object) }`
  - `readJson(req): Promise<any>`: 1 MB limit for normal requests (413 above). Invalid JSON → `HttpError(400,'Invalid JSON body')`. The import route passes `{limit: 20_000_000}`.
  - `sendJson(res, status, body)`. Status 204 sends no body.
  - `serveStatic(req, res, {root: string, mounts: Record<urlPath, absFilePath>}): Promise<boolean>`: GET/HEAD only. Prevents path traversal (resolved path must stay inside root), sets content types (html, css, js, json, webmanifest, png, svg, wasm → `application/wasm`), `/` → `index.html`. Returns false when nothing matched.
  - `createRouter(): { add(method, pattern, handler, {status=200}={}), handle(req, res): Promise<boolean> }`. A handler receives `{req, params, query: URLSearchParams, body}` (body parsed for POST/PUT/PATCH) and returns the response body.
  - `requireNumber(v, field, {min, max}): number`, `requireString(v, field, {maxLength=200}): string` (trimmed, non-empty), `optionalString(v, field, {maxLength=200}): string|null`. They throw `HttpError(400, '<field> must be …')`.
  - `openDb(filename: string): DatabaseSync`: `foreign_keys=ON`, `journal_mode=WAL`, migrations keyed by `PRAGMA user_version`.
  - Schema v1 (all tables created here; later tasks only query them):
    - `settings(key TEXT PK, value TEXT)`: JSON values
    - `ingredients(id INTEGER PK, name TEXT NOT NULL, brand TEXT, barcode TEXT UNIQUE, kcal REAL NOT NULL, protein REAL NOT NULL, carbs REAL NOT NULL, fat REAL NOT NULL, fiber REAL NOT NULL DEFAULT 0, source TEXT NOT NULL DEFAULT 'manual', archived INTEGER NOT NULL DEFAULT 0, created_at TEXT, updated_at TEXT)`
    - `portions(id INTEGER PK, ingredient_id INTEGER NOT NULL REFERENCES ingredients ON DELETE CASCADE, label TEXT NOT NULL, grams REAL NOT NULL)`
    - `meals(id INTEGER PK, name TEXT NOT NULL, created_at TEXT, updated_at TEXT)`
    - `meal_items(id INTEGER PK, meal_id INTEGER NOT NULL REFERENCES meals ON DELETE CASCADE, ingredient_id INTEGER NOT NULL REFERENCES ingredients, grams REAL NOT NULL, position INTEGER NOT NULL)`
    - `entries(id INTEGER PK, date TEXT NOT NULL, slot TEXT NOT NULL CHECK(slot IN ('breakfast','lunch','dinner','snacks')), ingredient_id INTEGER NOT NULL REFERENCES ingredients, name TEXT NOT NULL, brand TEXT, grams REAL NOT NULL, kcal REAL NOT NULL, protein REAL NOT NULL, carbs REAL NOT NULL, fat REAL NOT NULL, fiber REAL NOT NULL, position INTEGER NOT NULL)`. Nutrient columns are the per-100 g snapshot. Index on `(date)`.
  - `createApp({db, offClient, today: () => string, publicDir}): (req,res)=>Promise<void>`. Routes `/api/*` first; an unknown `/api` path → 404 JSON; then static. `HttpError` → `{error: message, ...extra}` with its status. Any other error is logged with method and path → 500 `{error:'Something went wrong'}`. `GET /api/health` → `{ok:true}`.
